The loop

Propose. Approve or edit. Execute.

Impri never executes anything itself. It holds the queue and the decision — your agent proposes, a human decides, your agent executes only on approve.

01

Propose

Your agent POSTs an action with a preview — a refund, an email, a deploy, a publish — before it does anything.

02

Approve or edit

A human approves, edits the draft, or rejects it — from the web inbox, Slack, Telegram, Discord, email or their phone.

03

Execute

The decision returns via webhook or polling. Your agent executes the approved (possibly edited) version — never the original draft.

Optional: a watcher can kick off step one automatically by polling RSS, Reddit or a page for changes.

New to this? Read What is an approval inbox? and Human-in-the-loop for AI agents, explained.

Why it's safe

Built as a safety layer, not a bot.

Fail-closed by default

Pending and expired actions never execute. The code path that sends the email or issues the refund is unreachable until an explicit human approve comes back.

Edit, don't just reject

A reviewer can tweak the draft before approving. The diff against the original ships inside the same signed payload your agent already receives.

Immutable audit trail

Every decision is append-only — no update or delete route exists for an audit row. GDPR erase leaves a tombstone showing an erasure happened, not a gap.

Signed webhooks

Every decision webhook carries an HMAC-SHA256 signature, timestamp and nonce — verify it before you trust the payload, or just poll instead.

Five lines

Push an action.
Wait for the human.

One POST puts a draft in the inbox. Your agent polls (or gets a webhook) and only acts on the decision — approved, rejected, or edited. Same flow from an MCP tool.

How to add human approval →
agent — bash
$ curl -X POST https://api.impri.dev/v1/actions \
    -H "Authorization: Bearer im_…" \
    -H "Content-Type: application/json" \
    -d '{
      "kind": "payment.refund",
      "title": "Refund $84.00 — order #10432",
      "preview": { "body": "Item arrived cracked, ticket #6021" },
      "payload": { "order_id": "10432", "amount_cents": 8400 },
      "editable": ["payload.amount_cents"]
    }'

→ 201 { "id": "act_5jf8", "status": "pending" }
# …human approves the amount in the inbox…
→ approved  agent executes the refund ✓
